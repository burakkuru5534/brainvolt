# Schema — identity, profile, devices

- **Roadmap task:** 0.2.2
- **Status:** Accepted (2026-10-15)
- **Modules / Postgres schemas:** `identity`, `profile`, `notification` (devices only)
- **Decisions applied:** D-002 (TR/EN), D-011 (Android + iOS), D-013 / D-013a (sign-in methods, guest upgrade), D-014 (single Firebase project), D-015 (link conflict), D-016 / D-016a (restricted-account limits), D-017 (email verification), D-020 (age gate), D-021 (avatars), D-022 (retention)

The SQL below is a **design specification**, not a migration. Real migrations are written in Phase 1 (identity, profile, devices) from this document. Conventions for all schemas:
- Primary keys `uuid` holding **UUIDv7** (ADR-0002), generated by the backend.
- All timestamps `timestamptz`, stored in UTC.
- Enumerations as Postgres `text` + `CHECK` constraint (easier to extend than `CREATE TYPE … ENUM`).
- `created_at` / `updated_at` on every mutable table; `updated_at` maintained by the application.
- Case-insensitive text via `citext` where uniqueness must ignore case.

---

## 1. Source of truth

| Data | Source of truth | BrainVolt copy |
|---|---|---|
| Credentials, passwords, Google/Apple tokens | **Firebase Auth** | never stored |
| Which sign-in methods are linked, email, email verified | Firebase Auth | **mirrored** in `identity.auth_identities`, refreshed from the verified ID token |
| Account tier (guest / unverified / full) | **derived** from the mirror | stored in `identity.users.account_tier` for fast checks |
| Account status, roles, profile, settings, devices | **BrainVolt Postgres** | — |

The mirror is refreshed by `POST /v1/session` (called by the app after every sign-in, link or email verification; contract in 0.4.2) using claims from the verified Firebase ID token (`sign_in_provider`, `firebase.identities`, `email`, `email_verified`). Every authenticated request also compares the token's provider/verification claims with the cached tier and resyncs on mismatch, so a stale tier can never grant more than Firebase says.

## 2. `identity` schema

```sql
CREATE EXTENSION IF NOT EXISTS citext;
CREATE SCHEMA identity;

CREATE TABLE identity.users (
  id              uuid        PRIMARY KEY,                 -- UUIDv7, the user_id used everywhere
  firebase_uid    text        NOT NULL UNIQUE,             -- never changes, also not after account upgrade (D-013a)
  account_tier    text        NOT NULL DEFAULT 'guest'
                  CHECK (account_tier IN ('guest','unverified','full')),
  status          text        NOT NULL DEFAULT 'active'
                  CHECK (status IN ('active','suspended','deleted')),
  age_verified_at timestamptz NOT NULL,                    -- 13+ self-confirmation on first launch (D-020); no birth date stored
  upgraded_at     timestamptz,                             -- first time tier became 'full'
  abandoned_at    timestamptz,                             -- guest left via link conflict (D-015); see §5
  deletion_requested_at timestamptz,                       -- user asked to delete account; see §6
  deleted_at      timestamptz,                             -- PII scrubbed
  last_seen_at    timestamptz NOT NULL,
  created_at      timestamptz NOT NULL,
  updated_at      timestamptz NOT NULL,
  CHECK (status <> 'deleted' OR deleted_at IS NOT NULL)
);
CREATE INDEX users_guest_cleanup_idx ON identity.users (last_seen_at)
  WHERE account_tier = 'guest' AND status = 'active';

-- Mirror of Firebase-linked sign-in methods
CREATE TABLE identity.auth_identities (
  user_id         uuid        NOT NULL REFERENCES identity.users(id) ON DELETE CASCADE,
  provider        text        NOT NULL CHECK (provider IN ('anonymous','google','apple','password')),
  provider_uid    text,                                    -- Google/Apple subject; NULL for anonymous & password
  email           citext,                                  -- NULL for anonymous; Apple may give a relay address
  email_verified  boolean     NOT NULL DEFAULT false,
  linked_at       timestamptz NOT NULL,
  last_sign_in_at timestamptz,
  PRIMARY KEY (user_id, provider)
);
CREATE UNIQUE INDEX auth_identities_provider_uid_uq
  ON identity.auth_identities (provider, provider_uid) WHERE provider_uid IS NOT NULL;
CREATE UNIQUE INDEX auth_identities_password_email_uq
  ON identity.auth_identities (email) WHERE provider = 'password';

-- Staff roles; 'player' is implicit for everyone
CREATE TABLE identity.user_roles (
  user_id     uuid        NOT NULL REFERENCES identity.users(id) ON DELETE CASCADE,
  role        text        NOT NULL CHECK (role IN ('moderator','admin')),
  granted_by  uuid        REFERENCES identity.users(id),
  granted_at  timestamptz NOT NULL,
  PRIMARY KEY (user_id, role)
);
```

### 2.1 Tier derivation (single function, unit-tested)
| Linked methods | Tier |
|---|---|
| `anonymous` only | `guest` |
| `password` with `email_verified = false`, and no `google`/`apple` | `unverified` |
| any `google` or `apple`, **or** `password` with `email_verified = true` | `full` |

Restricted account = `guest` or `unverified` (D-016, D-017).

### 2.2 What each tier may do (enforced in services, not only in the app)
| Capability | guest | unverified | full |
|---|:-:|:-:|:-:|
| Play casual & ranked, rating/XP/SP progress kept | ✓ | ✓ | ✓ |
| Random-queue 2v2 / 3v3 / 4v4 on temporary sides (D-016a) | ✓ | ✓ | ✓ |
| Join a private room / accept a challenge via invite code | ✓ | ✓ | ✓ |
| Appear on **public** leaderboards (Country, Global) | ✗ | ✗ | ✓ |
| Send / accept friend requests | ✗ | ✗ | ✓ |
| Create or lead a persistent team / couple profile | ✗ | ✗ | ✓ |
| Change username | ✗ | ✗ | ✓ |

Blocked actions return a dedicated error code (`ACCOUNT_UPGRADE_REQUIRED`, registry in 0.4.7) so the app shows the upgrade prompt (D-016a).
Ratings, XP and SP of restricted accounts are tracked normally; they simply become visible on public boards after upgrade.

## 3. `profile` schema

```sql
CREATE SCHEMA profile;

CREATE TABLE profile.profiles (
  user_id              uuid        PRIMARY KEY REFERENCES identity.users(id) ON DELETE CASCADE,
  username             citext      NOT NULL UNIQUE
                       CHECK (username ~ '^[a-z0-9_.]{3,20}$'),  -- handle used for friend search
  display_name         text        NOT NULL CHECK (char_length(display_name) BETWEEN 2 AND 24),
  avatar_id            text        NOT NULL,                       -- built-in preset key only; no photo uploads (D-021)
  country_code         char(2)     CHECK (country_code ~ '^[A-Z]{2}$'),
  locale               text        NOT NULL DEFAULT 'tr' CHECK (locale IN ('tr','en')),
  username_changed_at  timestamptz,
  country_changed_at   timestamptz,
  created_at           timestamptz NOT NULL,
  updated_at           timestamptz NOT NULL
);
CREATE INDEX profiles_country_idx ON profile.profiles (country_code);

CREATE TABLE profile.settings (
  user_id                 uuid    PRIMARY KEY REFERENCES identity.users(id) ON DELETE CASCADE,
  challenges_from         text    NOT NULL DEFAULT 'everyone'
                          CHECK (challenges_from IN ('everyone','friends','nobody')),
  show_online_status      boolean NOT NULL DEFAULT true,
  allow_friend_requests   boolean NOT NULL DEFAULT true,
  sound_enabled           boolean NOT NULL DEFAULT true,
  music_enabled           boolean NOT NULL DEFAULT true,
  haptics_enabled         boolean NOT NULL DEFAULT true,
  updated_at              timestamptz NOT NULL,
  profile_private         boolean NOT NULL DEFAULT false  -- D-101 (migration 000025)
);
```

Rules:
- **Created automatically** for every new user (in the same transaction as `identity.users`): username `oyuncu` + random digits (e.g. `oyuncu48213`), display name `Misafir 4821` / `Guest 4821` per locale, random preset avatar, country from device region (if provided), locale from device.
- **Username** change: full accounts only, at most once per 30 days.
- **Country** change: at most once per 30 days (prevents country-leaderboard hopping).
- **Display name** and **username** pass the profanity/impersonation filter (moderation, Phase 8; a basic word list from Phase 1).
- Email is **never** stored in `profile` and never returned by public profile endpoints.
- **Private profile** (D-101): with `profile_private` the player's stats (level, matches, wins, badges, streak) are shown only to the player and their friends; name, avatar and country stay public (leaderboards, matches), and friend requests still follow `allow_friend_requests`. A block hides the stats both ways.

## 4. `notification.devices` (stored from Phase 1, used in Phase 9)

```sql
CREATE SCHEMA notification;

CREATE TABLE notification.devices (
  id               uuid        PRIMARY KEY,
  user_id          uuid        NOT NULL REFERENCES identity.users(id) ON DELETE CASCADE,
  installation_id  text        NOT NULL,          -- random UUID generated by the app on first launch
  platform         text        NOT NULL CHECK (platform IN ('android','ios')),
  fcm_token        text        UNIQUE,            -- NULL until push permission granted
  app_version      text        NOT NULL,
  locale           text        NOT NULL CHECK (locale IN ('tr','en')),
  last_seen_at     timestamptz NOT NULL,
  created_at       timestamptz NOT NULL,
  revoked_at       timestamptz,
  UNIQUE (installation_id)
);
CREATE INDEX devices_user_idx ON notification.devices (user_id) WHERE revoked_at IS NULL;
```
- A device belongs to **one user at a time**. When the app signs into a different user on the same installation (e.g. after a link conflict, D-015), the row is **re-assigned** to the new user (upsert on `installation_id`), so pushes never reach the wrong account.
- FCM tokens reported invalid by FCM set `revoked_at`.

## 5. Flows

### 5.1 First launch (guest)
0. Age gate (D-020): app shows a one-time "I am 13 or older" / "13 yaşından büyüğüm" checkbox before anything else. Without it the app cannot continue; nothing is created in Firebase or BrainVolt.
1. App signs in anonymously with Firebase → gets ID token.
2. `POST /v1/session` (body includes `age_confirmed: true`; missing/false → error `AGE_CONFIRMATION_REQUIRED`) → backend verifies token; no `identity.users` row for this `firebase_uid` → in **one transaction**: insert `users` (tier `guest`, `age_verified_at = now()`), `auth_identities` (`anonymous`), `profiles`, `settings`; enqueue `identity.UserRegistered`.
3. Idempotent: repeating the call returns the same user (unique `firebase_uid`).

### 5.2 Guest upgrade (D-013a)
1. App calls Firebase `linkWithCredential` (Google / Apple / email-password). Firebase keeps the **same UID**.
2. App refreshes the ID token and calls `POST /v1/session`.
3. Backend inserts the new `auth_identities` row, recomputes tier, sets `upgraded_at` if tier became `full`, enqueues `identity.AccountTierChanged`.
4. Nothing else changes: `user_id`, match history, rating, XP, SP stay. Consumers react to `AccountTierChanged` (e.g. ranking adds the user to public leaderboards).

### 5.3 Email verification (D-017)
User verifies via Firebase email link → app refreshes token → `POST /v1/session` sees `email_verified = true` → tier `unverified → full`, `identity.AccountTierChanged`.

### 5.4 Link conflict (D-015)
1. `linkWithCredential` fails with Firebase `credential-already-in-use`.
2. App shows: *"Bu hesap zaten kayıtlı. Misafir ilerlemen kaybolacak. Devam edilsin mi?"* / EN equivalent. Cancel = stay guest.
3. On confirm: app calls `POST /v1/session/abandon-guest` **with the guest's token** → backend sets `abandoned_at`, removes the guest from queues/rooms, enqueues `identity.GuestAbandoned`. (If this call can't be made, the cleanup job in §6 covers it.)
4. App signs in with the existing credential → `POST /v1/session` returns the existing user; device row re-assigned (§4).
5. **No merge** of any data.

### 5.5 Suspension
`moderation` applies a sanction → `identity` sets `status = 'suspended'` (event `identity.UserStatusChanged`). Suspended users can sign in and see their profile and the sanction notice, but cannot queue, join rooms, chat or challenge.

## 6. Retention & deletion  (D-022)

| Case | Rule |
|---|---|
| **Abandoned guest** — guest with **0 completed matches** and no activity | Deleted when `last_seen_at` is older than **7 days**. |
| **Link-conflict guest** (D-015, `abandoned_at` set) | Deleted **7 days** after `abandoned_at`, whatever its match count — the owner explicitly chose to leave it. |
| **Inactive guest** — guest with **≥1 completed match**, never upgraded | Deleted when `last_seen_at` is older than **90 days**. |
| **User-requested deletion** (required by App Store & Google Play) | In-app "Delete account" sets `deletion_requested_at`. **14-day** cooling-off window: signing in and choosing "Cancel deletion" clears it. After 14 days the purge runs (below). |
| Unverified email accounts | Not deleted automatically; they keep their progress and limits (D-017). |

**Purge** (one River job per user, idempotent): Firebase user deleted via Admin SDK; `auth_identities`, `settings`, `devices` removed; `profiles` row anonymised (`username` = `deleted_<short id>`, display name "Silinmiş kullanıcı" / "Deleted user", default avatar, country NULL); `users.status = 'deleted'`, `deleted_at` set; event `identity.UserDeleted` so every module scrubs its own personal data (chat messages, creator quiz author name, …).

**Kept after purge:** `users.id` only, so match results, leaderboard history and moderation records stay consistent with no personal data attached.

**Match count for the guest rules:** `identity` may not import `game` (`backend-modules.md` §2). The cleanup job therefore uses a narrow `ActivityReader` interface declared in `identity` and implemented by `game` (completed-match count per user), wired in `internal/app` — same pattern as `matchmaking`'s `RatingReader`.

## 7. Events produced (added to `backend-modules.md` catalogue)
| Event | When | Main consumers |
|---|---|---|
| `identity.UserRegistered` | first `POST /v1/session` | profile (already created in-tx), progression, notification |
| `identity.AccountTierChanged` | tier changes | ranking (public boards), social, team, notification |
| `identity.GuestAbandoned` | link-conflict confirm | matchmaking, lobby, realtime |
| `identity.UserStatusChanged` | suspend / reinstate | matchmaking, lobby, realtime, chat |
| `identity.UserDeleted` | deletion executed | all modules holding personal data |

## 8. Resolved points
| # | Decision |
|---|----------|
| D-020 | Minimum age **13+**; one-time confirmation checkbox on first launch; only `age_verified_at` stored, never a birth date |
| D-021 | Built-in preset avatars only at launch, no photo uploads; cosmetic avatar frames and custom badges in Phase 9 |
| D-022 | Retention: abandoned guest (0 matches) 7 days; inactive guest (≥1 match) 90 days; user deletion 14-day cooling-off then purge/anonymise. Link-conflict guests: 7 days after abandonment (applied by extension of the abandoned-guest rule) |
